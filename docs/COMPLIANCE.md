# 合规边界与使用范围

feedkeep 是面向**已获授权的公开订阅源**的离线归档工具。仓库自带数据全部是合成 fixture，不含真实凭据、真实组织、真实域名或真实个人邮箱。

## 1. 允许的用途

- 在自己的机器或受控 CI 环境中，对已获授权的 RSS / Atom / JSON Feed 做增量归档；
- 保存条目标题、正文、时间、链接与附件元数据，用于内部审计、变更追踪与可重复评测；
- 在完全离线的环境中使用内置 mock 服务复现抓取、失败隔离和报告流程；
- 作为学习条件请求、幂等归档、SQLite 事务与审计报告的示例工程。

## 2. 禁止或不应使用的场景

- 未经授权抓取需要登录、付费、验证码或明确禁止自动访问的内容；
- 绕过访问控制、验证码、速率限制、付费墙或其他技术措施；
- 使用代理链、UA 轮换、请求指纹伪装等方式规避对方的识别或限制；
- 对目标服务实施压力测试、批量并发抓取或拒绝服务；
- 下载、转存或再分发音频、视频、PDF 等附件二进制；
- 将归档内容用于侵犯版权、隐私、商业秘密或其他违法用途；
- 把本项目当作通用网页爬虫、页面变更监测器或全文检索系统。

## 3. 网络行为约束

- 运行期目标主机必须精确命中策略白名单；
- 白名单值只允许 `127.0.0.1`、`localhost`、`::1` 回环别名；
- 非白名单 URL 在建立连接前拒绝，不进行 DNS 查询；
- 重定向目标重新校验白名单；
- 不使用系统代理环境变量；
- 同主机请求之间强制最小间隔，默认 200ms，配置下界 100ms；
- 单次请求有连接/读取超时、响应体上限；
- 单源单轮有条目处理上限；
- 4xx（429 除外）不重试；可重试错误有次数上限和退避上限。

这些限制是产品边界，不应通过修改代码来规避对第三方服务的基本礼貌与合同义务。

## 4. 声明身份，不伪装

请求只带最小头：

```text
Accept: ...
User-Agent: feedkeep/0.1 (offline feed archiver; local evaluation)
If-None-Match: ...            # 可选
If-Modified-Since: ...        # 可选
```

工具不提供：

- User-Agent 轮换池；
- Cookie / Authorization 注入；
- 请求指纹伪装；
- 代理链或 Tor 集成；
- 验证码识别或处理；
- 自动表单提交或登录流程。

## 5. 数据与密钥

- 配置样例与 fixture 只包含 `127.0.0.1` 合成 URL；
- 不写入 API key、Bearer token、Cookie、真实账号或真实邮箱；
- 运行产生的 SQLite 与报告可能包含订阅源正文，应放在受控目录并遵守组织的数据保留策略；
- 建议将 `data/`、`reports/` 与本地数据库排除在版本控制之外（仓库 `.gitignore` 已给出示例）；
- 日志不记录请求头中的认证信息，因为项目根本不发送认证信息。

## 6. 安全实现要点

- XML 解析显式拒绝 `DOCTYPE` / `ENTITY`，降低 XXE 与实体扩展风险；
- 响应体流式读取并设上限，避免无限下载；
- URL 在连接前校验 scheme、用户信息、控制字符、反斜杠与主机白名单；
- SQLite 开启外键，事务化写入，避免半写状态；
- 条目单条失败隔离，不让单个坏条目拖垮整源；
- 解析器不执行 HTML、脚本或附件内容。

## 7. 第三方内容与许可

订阅源内容权利归发布方所有。feedkeep 只提供技术能力，使用者需要自行确认：

- 是否有权访问、存储与使用目标内容；
- 是否遵守目标站点的服务条款、robots 约定、速率要求与版权许可；
- 是否需要为内部留存设置访问控制、加密与删除周期。

项目中所有合成条目标题、作者名与正文均为测试数据，不对应任何真实主体。项目代码采用 MIT 许可（见 `pyproject.toml`）。
